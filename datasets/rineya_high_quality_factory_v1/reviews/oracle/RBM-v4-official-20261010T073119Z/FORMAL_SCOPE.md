# Official prospective V4 formal checker scope

Author and actual runner: `/root/formal_oracle`. This is public-contract formal
authorship by the same underlying model and author of the reused V1–V3 code. It
is not a fresh independent-model review, a blind data review or an approval.

The V4 clarification's “Explicit inheritance” paragraphs require closed inline
claim fields and ordered E/G or F/H evidence for the two inherited names. Its
“Resolvable length-specific evidence” paragraphs require named-entry minimum
fields, exact complete candidate custody and recomputed comparison/prefix proof.
The new encoding addendum numbered paragraphs 1–3 make owner coordinates,
actual observation length, the published collection and unique composite lookup
mandatory. Its following paragraphs preserve aggregate V3 controls, permit open
manifest diagnostics and make pair_record_hashes optional.

The checker reuses unchanged independently authored V3, V2 and V1 primitives for
typed support/partition semantics, truthful property tags and locators, source
profiles, complete A–H relations, independently executed scoped probes,
27-schedule crossings, both styles, fact-local transposition and the 3,456-row
cohort. Initial source, tests, runner, public documents and dependency bytes are
bound in first-preexecution-freeze.json, before any new code import or execution.

The new interface is check(row) returning list[str], and check_batch(rows,
manifest_sources=None, candidate_bytes=None, previous_rows=None) returning an
object containing errors and counts plus full inherited and V4 derived evidence.
manifest_sources is an explicit caller byte ledger: repository-relative paths
map to actual raw manifest bytes. The caller binds that ledger to actual files;
the checker hashes and parses the supplied bytes and never treats a pointer as
proof. Missing candidate or manifest bytes fails closed as UNKNOWN.

Candidate records and passed records independently recompute the full canonical
record hash. A passed accepted row may differ from its preserved candidate only
in record_hash, review_status, review_receipt_ids and reviewed_candidate_hash;
the last resolves the original candidate record hash. Candidate manifest hashes
bind preserved PENDING candidate bytes, not a later accepted file's bytes.
The parent explicitly authorized the public factory/common.py hash formula and
canonical schema read; the checker reimplements that formula and imports no
producer, reference or gate code.

Resolved entry diagnostic annotations have no privately invented required
syntax. The checker receipt independently derives the actual typed field edit,
individual support, first-prefix IDs, empty/nonempty final supports, repeat and
full query partitions. Extra manifest annotation fields are neither trusted as
proof nor asserted to have been factually audited. ID spellings and global ID
uniqueness are not gates. Exact ID + name + ordered pair uniqueness is a gate.

previous_rows optionally proves stable-coordinate task/rendered-input/full typed
target preservation against supplied prior rows, rederiving the target. Without
that input, the report explicitly says NOT_RUN and permits no zero-growth claim.
This optional proof does not by itself bind prior rows to a historical raw file;
the production caller must separately preserve and hash the actual prior file.
Fresh producer source/version custody and separate review/adjudication also
remain production responsibilities; no private version spelling is a hard gate.

All executed new inputs are independently handwritten finite toy/cohort
fixtures. No actual V3/V4 candidate, gold, producer implementation, real manifest
or reviewer/adjudication judgment is read. No factory, released artifact,
earlier checker, earlier test, or completed prospective preparation is modified.
The new active official prefix is intentionally deferred from the concurrent
RGM release inventory. Exact validated bytes may later be promoted unchanged by
the parent in a separately authorized integration.
