## Canonical changed-clearance witness

For V2, a `later_action_requires_changed_block_clearance` witness's `evidence` must contain:

| Field | JSON type and exact meaning |
|---|---|
| `action_index` | Integer, excluding bool, `1 <= i < len(plan)`. The action at `i` is legal after the submitted, actually legal prefix. |
| `precondition` | Exactly the string `source_not_clear` or `destination_not_clear`, selected by the initial-state rule below. |
| `enabling_action_index` | Integer, excluding bool, `0 <= j < i`. The actual submitted action at `j` moves the initially obstructing block away and changes the selected object's clearance from false to true. |
| `obstructing_block` | Existing block-name string. In the initial state it is directly on the selected source or destination object; it is the block moved at `j`. |

Extra diagnostic fields may be supplied but cannot replace these four fields or introduce another property definition. All referenced names, actions and supports must be checked against that row's parsed task; a well-typed annotation alone proves nothing.

For the action at `i`, let `b=action.block`, `d=action.to`, and evaluate clearance in the initial `on` map. Initial canonical selection is: if `b` is not clear, use `source_not_clear`; otherwise, if `d != "TABLE"` and `d` is not clear, use `destination_not_clear`. If neither holds, this property has no witness. When both are initially blocked, `source_not_clear` is the canonical selection. This precedence applies to this diagnostic witness only; it adds no reason-code field or new precedence to the existing target schema.

At the actual prefix, the entire action at `i` must be legal under unchanged dynamics. Immediately before and after action `j`, the selected object's clearance must respectively be false and true; the initial direct obstruction must really have been moved. The object must be clear immediately before `i`. A later intervening reblocking is permitted only if the stored `j` still satisfies those checks and a separately recorded diagnostic explains it; claiming one earlier action alone proves permanent clearance is forbidden. The chosen initial code still must follow the canonical rule. State-search or prefix timeout yields no witness.

For example, the encoding fragment `{"action_index":2,"precondition":"source_not_clear","enabling_action_index":1,"obstructing_block":"cap"}` means that action 2's source was initially blocked by `cap`, action 1 actually cleared it, and action 2 is now legal. The analogous fragment with `precondition="destination_not_clear"` requires its source to have been initially clear and its non-TABLE destination initially blocked. These are type/meaning examples, not production tasks or expected answers; the names and indices are not assumed to exist in any future row.

Reject `"source"`, `"destination"`, `"blocked_source"`, `"blocked_destination"`, arbitrary synonyms, integers, bools, null, lists and objects as this field's V2 value. Reject a false code even when the other clearance predicate is initially false. TABLE cannot witness destination-not-clear. Reject indices outside the plan, nonexistent obstructions, legal-initial actions, illegal actual prefixes/actions, and an alleged enabling move that does not clear the selected object. No string coercion, type coercion, alias translation or silent repair is allowed. The original V1 field was unspecified; these exclusions are prospective V2 requirements.

## Decisive C1 clearance controls

C0 remains a legal canonical minimum-move goal plan of 4–8 moves with a changed-clearance witness. C1 changes only its plan by exchanging one adjacent action pair; its world and goal and plan length remain identical. Its actual first failure must be one of the canonical diagnostic reason strings above. For a first `destination_not_clear` failure, source/name/distinctness conditions must pass so that omitting only destination clearance accepts that action. For a first `source_not_clear` failure, the source really is obstructed. The strict replay stops at its first illegal action and preserves state; no later action supplies the intended witness.

The existing `adjacent_action_order_counterfactual` control additionally has an `evidence` object with integer, non-bool `swap_index`, integer, non-bool `first_failure_index`, and `first_failure_reason` equal to the actual string `source_not_clear` or `destination_not_clear`. `swap_index` selects the exchanged pair in C0. The failure index is measured by replay and is not assumed equal to the swap index. Both actual sample IDs/renderers must be bound by the original control structure.

Require six source failures and six destination failures, each comprising three five-block and three six-block families, with five train and one exposed-dev family. Require at least three distinct first-failure indices across C1, at least two within each reason class, and at least one failure after a nonempty legal prefix within each reason class. An initially false *changed-clearance* witness and a *C1 first-failure* reason are different measurements and must not be substituted for one another. Row tag `legal_prefix_then_first_failure` applies only when the actual first index is at least one.

## C4: supplied isolated no-op controls

Each of the twelve C families adds exactly one C4 semantic input under its unchanged C0 `on` and `goal_on`. Select a canonical C0 prefix of length `k=1,2,3` according to the public allocation in the V2 curriculum; it is legal and does not achieve the goal. C3 now supplies exactly that prefix. C4 appends one action moving an actually clear block whose current support is TABLE to TABLE again. It changes no task field except `plan` and has length `k+1`; no suffix is needed.

Thus names/existence, source clearance, TABLE destination, and source/destination distinctness all pass at the appended action; only the unchanged-support prohibition fails. This isolates the no-op requirement. Appending a move onto its already occupied non-TABLE support does not satisfy this control: it also violates destination clearance.

The NEW optional per-row property `isolated_unchanged_support_failure_after_legal_prefix` is true only for a block row satisfying that complete replay condition. Its witness evidence requires integer non-bool `action_index=k>=1`, existing block-name string `block`, and string `current_support="TABLE"`; check all earlier actions legal, the selected source clear/on TABLE just before `k`, submitted action exactly `{block,to:"TABLE"}`, and unchanged final state at the first illegal step. C4 must carry this property on both renderers; do not tag C0/C3 merely because their family contains C4. Existing legal-prefix failure property also applies to C4 with a separate truthful witness.

The NEW supplied control `isolated_noop_append_counterfactual` uses the existing control fields with `scope="corpus_variant"`, `provenance="supplied_tasks"`, exactly C3/C4 sample IDs, `changed_task_fields=["plan"]`, and `evidence={"prefix_length":k,"block":actual_name,"current_support":"TABLE"}`. C3's plan must be the exact first `k` C0 actions and C4's plan exactly that plan plus the declared no-op. This stronger C3 pairing is V2-specific; it does not reinterpret the original encoding supplement's prefix freedom.

## Transition mutation checks and publication unit

Before labels/reviews are approved, execute separate strict and deliberately mutated public-contract replay implementations. `destination_clear_ignored` removes only the non-TABLE destination-clear check; retain existence, source clearance, distinctness and unchanged-support checks, without a compensating post-transition validator restoring the omitted guard. `no_op_allowed` removes only the unchanged-support check and retains every other guard. These are deliberately incorrect diagnostic implementations, never label sources or new semantics.

Require a complete output/trace difference for every destination-failure C1 under the former mutant (6 semantic inputs/12 rendered rows, 5 train +1 dev family), and for every C4 under the latter (12 semantic inputs/24 rows, 10 train +2 dev families). Compare complete strict traces, not only terminal goal/valid booleans, since two wrong paths can share terminal categories. Every C4 must agree with strict replay under destination-clear omission, demonstrating isolation. Record measured affected tasks, first differing step, controls, split/size histograms, input hashes and actual execution completion. Those are precise bounded mutation kills, not proof that all incorrect solvers or shortcuts have been eliminated.

All original four contexts remain required in A/B/D and all five in C; both renderers and all supplied control bindings form the review cohort. Required temporary goal displacement remains independently proven for at least four C0 families. No incomplete/failed search can claim a property or feasibility. A target-correct member does not discharge a defective required pair/cohort.
