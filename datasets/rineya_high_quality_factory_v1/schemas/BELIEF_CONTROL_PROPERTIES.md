# Public factual properties for the RBM evidence gap

Design supplement to RBM-GAP-007, 2026-10-10 UTC. Actual author: `/root/research_architect`, Dataset Research Architect. This new file changes no existing `kind=belief` input/output semantics in `EXTENDED_SEMANTICS.md`, supplies no future world table or gold labels, and approves no production. It defines coverage claims that later independent implementations must prove from visible inputs.

## Definitions and witness scope

Let W be the visible set of world IDs and S0=W. For observation j, Sj is the subset of Sj-1 whose named fact equals the supplied scalar **with type-sensitive equality**. A world ID occurs once; all worlds have the same fact-key set. For query fact f, P(f,S) maps each typed scalar value found in S to its positive count. D(f,S) is the number of those bins. The existing contract defines entailed iff S is nonempty and D=1, and can_reduce_uncertainty iff D>1. Counts are unweighted multiplicities; they are not probabilities or entropy. Distinct worlds for these design controls must have different complete typed fact payloads, rather than differing only in world_id.

Null, booleans, integers and strings remain distinct. `guaranteed=null` has several interpretations determined by the other fields: entailed-null, ambiguity, or empty belief. The literal string `unknown` is an ordinary scalar, not a status or missing value. There is no selected hidden truth, likelihood, source authority, cost or inspection action in this contract.

Per-record property tags require witnesses inside that record's student-visible task. A sibling, producer annotation or provenance pointer cannot establish such a tag. Record witnesses identify actual query facts/IDs, observation indices, exact prefix survivor sets, typed bins and any comparisons required below. Internal evidence is not added to the student prompt. A property can be absent from a perfectly valid record; do not attach all tags to all six contexts.

## Per-record property names

| Property | Required input-derived witness |
|---|---|
| `multiworld_unobserved_invariant` | Final S has at least two distinct fact-payload worlds; a queried fact never occurs in observations, yet D(f,S)=1. This breaks the inference that every unobserved fact varies in a non-singleton support. A globally constant column can meet this basic property, but not the stronger conjunction property below. |
| `conjunction_required_invariant` | The preceding invariant witness holds, and at least two nominated observation indices constrain different facts. Removing either nominated observation while retaining all others gives at least two typed values for that same queried fact, whereas the full conjunction gives one. Thus both constraints are necessary for this invariant; merely counting two observations is insufficient. |
| `useful_after_conjunctive_evidence` | Final S is nonempty and a query has D>1 after at least two observations on distinct facts. At least two prefix steps strictly reduce support while keeping it nonempty. This certifies a distinguishing offered query after actual conjunctive filtering, not inspection utility or a chosen action. It does not by itself say that each filter was necessary for the usefulness flag. |
| `multiworld_all_queries_redundant` | Final S contains at least two worlds with different complete fact payloads; every offered query has D=1. At least one unqueried fact varies among these worlds. This separates remaining world uncertainty from usefulness of the offered queries without counting duplicate payloads as distinct states. |
| `multiworld_entailed_null` | Final S contains at least two distinct fact-payload worlds; a query has exactly one bin `(null,|S|)`, entailed=true and guaranteed=null. This is different from singleton-null and from an empty belief. |
| `ambiguous_null_partition` | A query's final bins contain null and at least one other typed value. D>1, entailed=false and guaranteed=null. Null is one possible value, not absence of a bin. |
| `cross_fact_inconsistent_conjunction` | Two supplied observations constrain different facts; each alone has a nonempty satisfying subset of the full visible W, but their intersection is empty. Both observations occur in the row, whose final support is therefore empty. An unsupported single observation or a same-fact dispute alone does not qualify. |
| `post_empty_absorption` | A prefix first reaches the empty set, and at least one later observation is supplied. At least one such later observation is individually satisfiable in W. Every later prefix stays empty and final query bins are empty. The ordinary later evidence cannot resurrect discarded worlds. |
| `nonempty_repeated_observation` | An observation exactly repeats an earlier `(fact,typed equals)` pair. Its incoming prefix support is nonempty and its outgoing support is identical, including IDs. Record the repeated indices and actual unchanged prefix cardinality. A repeated step after empty alone does not qualify. |
| `typed_observation_separator` | Immediately before an observation, survivors contain both its exact typed value and its numeric/boolean alias on the same fact: true versus integer 1, or false versus integer 0. The observation retains a nonempty exact-typed subset and excludes every alias-valued survivor. A type-coercing equality would retain a different set. The alias must be active before this step, not merely present somewhere in W. |
| `typed_query_partition_separator` | Final query bins contain both true and integer 1, or both false and integer 0, as distinct positive-count bins. Type-coercing binning would change D and/or the exact count list. No float or string-to-number alias is implied. |
| `skewed_possible_value_partition` | A query has at least two typed value bins and at least two positive bin counts differ. Certify the exact multiplicities. This is count imbalance, not a posterior distribution or information gain. |

Scalar bin ordering remains lexicographic ordering of each scalar's canonical JSON encoding, with ensure_ascii=false and no extra whitespace. Count only values actually present among survivors. Hash/prompt/target equality must also distinguish boolean and integer values; ordinary host-language equality is insufficient.

## Family controls and supplied versus probe coverage

Each family claim records one public identifier, a `scope` of `corpus_variant` or `audit_probe`, its source-family key, and exact pair/probe evidence. A claim asserts existence of a relationship in that same family at the named scope; it does not assert every row instantiates the relationship. Evidence pointers cannot substitute for an independently reconstructed witness. Audit-only transformations add zero corpus records and zero source families.

| Family control | Required relationship |
|---|---|
| `equal_support_usefulness_counterfactual` | A and B have identical worlds, ordered queries and observation count; change only the typed equals value of one observation. Both final supports have the same cardinality >=2, but at least one same query changes D>1 to D=1 or vice versa. Record exact changed field, old/new survivor sets, partitions and flags. Support size or observed-fact status alone cannot explain the change. |
| `observation_reorder_final_invariance` | C permutes A's same observation multiset while holding worlds/queries fixed. Final survivors and every full query answer agree, but each ordered prefix support/count is independently recomputed. The proposed corpus must contain at least one changed prefix cardinality; never claim belief_sizes are invariant to reordering. |
| `nonempty_repetition_final_invariance` | D is A followed by an exact repeat of one earlier observation. A's final support is nonempty; D's final survivors/query answers agree and its final added trace count equals that support size. |
| `cross_fact_contradiction_counterfactual` | E holds A's worlds and queries fixed and changes one observation equals value, producing an individually supported but jointly impossible different-fact pair. E's cross-fact contradiction must have its own per-record witness. |
| `post_empty_append_absorption` | F is E followed by an observation individually supported in W. E is already empty. F retains empty final survivors/query bins and appends a zero prefix count. |
| `typed_equals_counterfactual` | Paired rows/probes share worlds, queries and all other observations; toggle only one observation equals value between true/integer 1 or false/integer 0. Both alternatives have nonempty support at the changed prefix and exact-typed survivor sets differ. If one final belief later becomes empty, do not claim both final supports are nonempty. |
| `null_guarantee_contrast` | Same-family supplied rows/probes jointly exhibit multiworld entailed-null, an ambiguous query with a null bin, and empty-belief guaranteed-null. All three require their distinct exact counts/flags. This is a family relationship, not a per-row three-condition tag. |
| `query_id_position_fact_crossing` | Declare three stable decoded query-fact roles and independently vary ID shift u, position shift v and consistent queried-fact-name shift w over all of Z3 cubed. For each role and each base context/field order, every ID/position/name triple appears exactly once; each marginal bucket appears 9 times and each pair bucket 3 times. Rename the corresponding fact keys consistently in all worlds, observations and queries. Verify actual outcomes as well as the schedule. |
| `field_order_invariance` | Paired prompts differ only in JSON object field order, preserve typed values and all list orders, and have identical parsed tasks and complete targets. Observation-list permutation is a separate semantic trace control. |
| `world_order_invariance` | An actually executed corpus/probe world-list permutation preserves all outputs, including lexicographically sorted survivor IDs and ordered prefix counts. |
| `world_id_rename_equivariance` | Apply a bijection to all supplied world IDs. Fact payloads, observations and queries stay fixed. Prefix counts/query answers agree; survivor IDs are mapped and then sorted lexicographically anew. |

For query ID renaming/reordering probes, match query facts and exact output payloads after the corresponding ID/order mapping. Do not infer supplied corpus renaming/order coverage from an audit probe. No row-order-independent output is implied: query rows follow the supplied query list and belief_sizes follows the supplied observation list.

## Explicit pilot metadata encoding

These are canonical-record metadata, excluded from the student-visible task. They do not extend the existing task/output schema. The initial pilot must use the following documented encoding; checker and producer must not infer unpublished exact-key requirements from a different track's interface.

- `controlled_context` is exactly one of `A,B,C,D,E,F`. `structural_family_profile` is exactly one of `cyclic_uniform,acyclic_branching,cyclic_weighted,typed_path`, matched to indices 12,13,18,19 respectively and independently verified from the world table.
- `source_family_index` is one of 12,13,18,19, and `source_family_key` is one stable string for all descendants. Existing semantic parent/family/split fields remain governed by the canonical contract.
- `id_shift`, `position_shift` and `fact_name_shift` are integers 0..2; `schedule_index` is exactly `9*id_shift+3*position_shift+fact_name_shift`. Every family/context/renderer has all 27 indices once. `renderer` is `forward` or `reverse`, denoting only the paired object-field-order styles.
- `query_id_pool` and `queried_fact_name_pool` are ordered lists of three distinct strings. Pool order is declared, not inferred from lexicographic order. Each pool is fixed within a source family across contexts/views. Names must be arbitrary and equally styled. Queried fact names are consistently reassigned to roles by the schedule, never changed only in queries.
- `fact_role_assignments` maps the five required role keys `observation_control,observation_auxiliary,invariant_query,variation_query,unoffered_feature` to five distinct visible fact names. Extra facts are allowed only with additional declared role keys matching `aux_extra_[0-9]+`; all mapped names are distinct and together equal the world's fact-key set. Extra roles do not become extra queried roles or change planned counts. The observation_control fact is the third queried role. The two auxiliary core roles and any extras keep names outside the queried-name pool; broader crossing of those roles is not claimed.
- `query_role_assignments` is a list of exactly three objects, each with required keys `role,position,query_id` and optional `fact`. No other keys are allowed. Roles are exactly `invariant_query,variation_query,observed_control`, each once. They correspond to role indices r=0,1,2. Position is `(r+position_shift)%3`; query_id is `query_id_pool[(r+id_shift)%3]`; the visible queried fact is `queried_fact_name_pool[(r+fact_name_shift)%3]` and must equal the appropriate fact_role_assignments value. If optional fact is present it must match that same visible fact. These names denote stable decoded slots across contexts; they do not assert that a slot is invariant/useful/observed after every context's final evidence. In particular empty contexts have no entailed query.
- `skill_tags` contains the descriptive scope tags `finite_synthetic_proxy,finite_noiseless_filter,possible_value_partition`, plus only actually witnessed per-record property names from the table above. Family-control names and undefined aliases are excluded. Generic scope tags express the task domain, not model capability. A legitimate E/F row can have only the properties relevant to its empty/typed prefix evidence.
- `property_witnesses` is a map whose keys equal exactly the per-record property tags attached to the row. Each value is a **locator**, with exactly the required fields `query_ids,observation_indices,prefix_indices`; optional fields are `supporting_world_ids,note`. No other witness fields are allowed in this encoding. Query IDs are distinct existing visible IDs; observation indices are distinct integers 0..m-1; prefix indices are distinct integers 0..m, with 0 meaning full W before observations. Lists can be empty when that property needs no witness of that category. Prefix/observation locators must include the indices actually required by that property's definition. Optional supporting_world_ids is a sorted list of distinct existing world IDs, independently checked against the indicated supports and property. Note is a descriptive string without normative force. The checker independently recomputes all sets, counts, types and counterfactual omissions from visible inputs; locators are not answer oracles. Conjunction-required locators nominate the two observation indices whose separate omissions are recomputed.
- `family_control_claims` is a list of objects containing exactly one of `name` or `property`, with its value a public family-control identifier above, plus required `scope` equal to `corpus_variant` or `audit_probe`. Optional allowed fields are `source_family_key,evidence_manifest,control_id,pair_sample_ids,probe_id`; no other fields are allowed. Optional source_family_key must equal the row's family. evidence_manifest is a nonempty relative provenance string and is not credited as proof. control_id is a nonempty descriptive evidence key. pair_sample_ids, when supplied, is a two-element list of distinct actual same-family corpus IDs and requires corpus_variant scope. probe_id, when supplied, is a nonempty identifier of an actually executed same-family probe and requires audit_probe scope. Neither pointer/ID existence nor a producer claim can replace an independently reconstructed relationship. Conflicting name/property, unknown identifier/scope, duplicate claim identifiers with inconsistent scope, mismatched families and undeclared fields are errors.

The per-row witness locator fields deliberately carry no precomputed target/count payload. Later formal/expert/adversarial evidence must publish its own exact supports/partitions and validate these locators. This version does not accept the richer memory witness shape implicitly. If a future alternative encoding is wanted, publish it before candidate generation and initial review rather than fitting a checker to private expectations.

## Rotation assessment and measured histogram requirements

The expert's original nine schedules use, for role r in Z3, ID=r+u, position=r+v, name=r+u+v. Each role has uniform marginal/pair support, but `r=ID+position-name` mod 3. Each role therefore occupies a different nine-cell nuisance-triple plane. Pooling roles can hide this deterministic role leak. Nine schedules are not sufficient for a complete triple-support claim.

This design chooses independent 27 schedules: ID=r+u, position=r+v, name=r+w, with u,v,w independent. Every role occupies every nuisance triple once. This is the minimum positive uniform complete triple support:27 combinations must be covered per role. A modified nine-schedule construction can equalize roles on only nine shared cells, but leaves 18 cells unsupported and retains three-way coupling; that cheaper alternative is not the selected plan.

For each source/context/field-order set, derive real role-by-ID/position/name and role-by-pair/triple counts. Publish actual histograms of full typed query payloads (excluding the renamed query_id and fact-name identity), entailed/useful flags, empty/entailed/ambiguous audit categories, guaranteed-null with its entailment context, distinct_values, count-vector/type signatures, and support provenance (sorted final world IDs and exact prefix survivor/count signatures) for each nuisance marginal, pair and triple. Those categories/provenance signatures are internal evidence, not additional target fields. At every triple, each role appears once; its histogram therefore matches every other triple's histogram, even when class frequency is unequal. Validate the result from actual targets independently, rather than declaring success from an annotation. Keep comparisons within a base context before aggregating across contexts/splits.

Full per-query triple support does not remove all row-level patterns: cyclic shifts preserve cyclic role orders. Higher-dimensional row-pattern independence, world-ID/order style and unseen-mechanism generalization are not claimed. Independent arbitrary permutations would address a larger threat model at greater correlated-record cost and require a separately justified design.

## Counts, custody and semantic boundary

Selected source indices are 12,13,18,19: two train and two exposed-development families under the common split policy, checked before rendering. Planned counts are **4 source families x 6 contexts x 27 schedules x 2 field orders =1,296 correlated records**, 24 base cases,72 base case/query observations, 1,944 rotation-level query observations and 3,888 rendered query observations. Actual distinct world tables, tasks, renderings and query signatures must be measured. Renamings, contexts, probes and field orders do not become new source families or new mechanisms.

Every descendant of a family retains its split. Compare exact tasks/world tables and order-invariant partition/incidence signatures against prior releases; fresh numeric IDs do not certify freshness. All four structural profiles must differ beyond arbitrary world/fact names or scalar substitutions. This remains finite noiseless consistency filtering and possible-value partitioning. It supplies no Bayesian update, noisy evidence policy, authority, expected inspection utility, action selection, sealed OOD result or model efficacy.
